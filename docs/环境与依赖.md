# 环境与依赖清单

> 对应版本：M2.0（占位符 + 结构化对齐 + 动态扩行 + **DeepSeek 语义对齐**）
> 核对时间：2026-10-21，Windows 11 + Python 3.13.14 实测通过

## 一、运行环境

| 项 | 要求 | 说明 |
|---|---|---|
| 操作系统 | Windows / Linux / macOS | 无平台相关代码，路径统一用 `pathlib` |
| Python | **3.10+**，推荐 3.13 | 代码用 `X \| None` 联合类型注解，3.9 未实测 |
| 磁盘 | ≥ 400 MB | 依赖约 95 MB，任务文件按上传量增长 |
| 端口 | 8123（可改） | 单端口同时提供 API 和前端页面 |
| 浏览器 | Chrome / Edge 等现代浏览器 | 前端原生 JS，无构建步骤 |
| 外网 | **仅调用模型时需要** | 只出站访问 `api.deepseek.com` 的 443 端口 |

**不需要 Node.js / npm**：前端是 `web/index.html` 单文件，后端直接托管，改完刷新即生效。
**不需要向量库、不需要本地模型**：没有 chromadb、sentence-transformers、Ollama。

安装：

```bash

.venv\Scripts\activate

```

## 三、大模型接入（可选）

不配置也能跑，只是「待确认」的字段会少一些、字面不匹配的字段会保守地判为缺失。

### 配置方式

复制 `backend/.env.example` 为 `backend/.env`，填入 Key：

```ini
DEEPSEEK_API_KEY=sk-xxxxxxxxxxxxxxxx
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-chat
DEEPSEEK_TIMEOUT=90
DEEPSEEK_MAX_TOKENS=4096
```

也可以直接用环境变量，环境变量优先级高于 `.env`（方便容器化部署时不落盘密钥）。

改完重启服务生效，然后核对：

```bash
curl http://127.0.0.1:8123/api/llm/status   # enabled 应为 true
curl -X POST http://127.0.0.1:8123/api/llm/test  # 真实调用一次，返回延迟与模型名
```

页面顶部也有状态标签：绿色「语义对齐已启用」= 配置生效；灰色 = 仍是规则模式。

### 换成别的模型

只要兼容 OpenAI 协议就能直接用，改两个变量即可（通义千问、Kimi、vLLM、Ollama 都可以）：

```ini
DEEPSEEK_API_KEY=sk-xxx
DEEPSEEK_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
DEEPSEEK_MODEL=qwen-plus
```

内网私有化部署同理，把 `BASE_URL` 指向内网服务（如 `http://10.0.0.5:8000/v1`），数据不出域。
**但要求模型支持 `response_format: json_object`**，否则返回不是 JSON，会被降级处理。

### 数据合规（重要）

开启模型后，**上传的模板与参考资料原文会发送到模型服务商**。
处理涉密或敏感文档时，要么不配 Key（纯规则模式，数据不出本机），
要么把 `BASE_URL` 指向内网模型。

### 成本

单次处理一般 1~2 次调用（缺失字段不多时只有 1 次），约几千 tokens。
同一份资料重复处理会命中缓存（`storage/.llm_cache/results.json`），**第二次起零调用**。

## 四、四级取值链

| 级别 | 做法 | 性质 |
|---|---|---|
| ① 结构化对齐 | `{活动1名称}` → excel 第 1 行「活动名称」列 | 确定性，置信度 1.0 |
| ② 精确抽取 | 全量扫描，**字段名完整出现且后面真的带出了值**才算命中 | 确定性正则 |
| ③ 语义对齐 | 规则判不出来的字段交给 DeepSeek，整篇读资料找依据 | 模型，必须过代码校验 |
| ④ 追问用户 | 前三级都没有 → 生成具体追问，不带模型的猜测 | — |

③ 的每个结果都要过三道代码校验，任一不过就退回 ④：

1. 引用的资料块必须真实存在
2. 引用的原文必须**逐字**出现在该块里（防编造引文）
3. 取值必须能在该块原文中找到出处（防编造内容，日期允许换格式、长段落允许压缩）

通过校验的结果标记为**「待确认」而不是「已填」**——模型给的是候选值，不是事实。

## 五、启动

```bash
cd backend
python -m uvicorn app.main:app --host 127.0.0.1 --port 8123
```

浏览器打开 <http://127.0.0.1:8123>。

自检脚本：

```bash
python scripts/make_samples.py   # 造模板 + 参考文件
python scripts/smoke.py          # 完整链路，打印三态统计、扩行情况、导出核验
python scripts/test_llm.py       # 语义对齐 40 项离线测试，不需要 Key
```

`test_llm.py` 用假模型专门攻击校验层：编造引文、编造取值、引用不存在的块、
编造列名，逐个确认都被拒绝。它还带一个本地假 DeepSeek 服务，验证请求格式和鉴权头——
**没有 Key 也能确认模型层是通的**，只是真实模型效果得配 Key 后才看得到。

## 六、生产部署要注意的

1. **多进程**：`uvicorn --workers 4` 时任务元数据 `_index` 是**进程内字典**，
   请求落到别的 worker 会 404。上线前必须换成 Redis 或 SQLite。
2. **请求时长**：接了模型后单次处理 3~15 秒。Nginx 默认 `proxy_read_timeout 60s` 够用，
   但字段特别多时建议调到 120s。
3. **反向代理**：需放开上传体积（`client_max_body_size`），默认 1 MB 会挡掉大文件。
4. **文件存储**：任务文件落在 `backend/storage/tasks/<task_id>/`，会一直累积，需要清理策略。
5. **密钥管理**：`.env` 不要提交到 Git（已在 `.gitignore` 里）；容器部署用环境变量注入。
6. **端口绑定**：生产环境绑 `0.0.0.0` 而非 `127.0.0.1`，并置于反向代理之后。
7. **数据合规**：当前无鉴权、无加密。处理涉密文档前必须先加登录和传输加密，
   并按第四节判断是否允许把文件内容发往外部模型。
