# 文件处理 Agent

按模板自动填写文档，**每个填进去的值都必须能指回原文出处，找不到就明确告诉你缺什么**。

上传一份带占位符的 Word 模板，再上传参考资料（docx / xlsx / pdf / pptx），系统逐字段填充，并给出三态结果：已填 / 待确认 / 需补充。无依据的字段一律不猜。

## 解决什么问题

人工照模板写文档，最耗时的不是写，是**翻资料找依据**；最容易出事的不是写错，是**凭印象补一个看起来合理的值**。这个项目把这件事反过来做：

- 先拆解模板，得到一份字段清单（而不是把整篇文档丢给模型）
- 每个字段独立取数，取值必须有出处（结构化单元格 / 原文精确匹配 / 模型指出引文并经代码校验）
- 取不到就生成一句**具体的追问**（「缺少项目组成员名单，请上传或填写」），而不是写一句「信息不足」

## 取值链

每个字段按顺序走，命中即停：

| 级别 | 做法 | 结果 |
|---|---|---|
| ① 结构化对齐 | `{活动1名称}` → excel 第 1 行「活动名称」列 | 精确命中，置信度 1.0 |
| ② 规则精确抽取 | 字段名完整出现且后面紧跟 `：值` | 抽出候选值，待核对 |
| ③ 语义对齐（可选） | DeepSeek 通读全文，指出「哪段原文的哪几个字」 | 候选值 + 引文，待核对 |
| ④ 追问用户 | 前三级都拿不到 | 明确说明缺什么 |

③ 不是 RAG：不做向量化、不做 Top-K 召回，按 12000 字分批把全文交给模型，避免「正确片段被召回挤掉且不报错」这类静默失败。

## 防幻觉：模型的话不能直接进正文

模型只负责指出依据，输出必须过三道代码校验，任一不过即退回「需补充」：

1. 引用的资料块必须真实存在
2. 引用的原文必须**逐字**出现在该块中（防拼接、改写、编造引文）
3. 取值必须能在该块原文里找到出处（日期允许换格式，短清单要求逐项可溯，长段落允许归纳但要求 n-gram 覆盖率）

即使三道全过，结果也只标为**「待确认」**而不是「已填」——候选值需要人确认，系统不替你担保。

## 快速开始

```bash
cd backend
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python -m uvicorn app.main:app --host 127.0.0.1 --port 8123
```

打开 http://127.0.0.1:8123 即可试用。仓库内已备一套示例素材：

- 模板：`backend/storage/templates/网络安全计划模板.docx`
- 参考：`backend/storage/uploads/`（立项说明 docx、成员清单 xlsx、接口协议 xlsx）

**环境要求**：Python 3.10+（实测 3.13），无需 Node.js、无需向量库。详见 [docs/环境与依赖.md](docs/环境与依赖.md)。

### 接入大模型（可选）

不配置也能跑，只是降级为纯规则模式，字面不匹配的字段会保守判为缺失。

```bash
cp backend/.env.example backend/.env
# 填入 DEEPSEEK_API_KEY 后重启
```

兼容 OpenAI 协议，改 `DEEPSEEK_BASE_URL` 即可指向通义、Kimi 或内网 vLLM，代码不用改。

> ⚠️ 启用后，**模板与资料原文会发送到模型服务商**。涉密文档请勿配置 Key（纯规则模式数据不出本机），或将 BASE_URL 指向内网模型。

## 模板约定

模板里用 `{}` 占位符标记待填位置，出现 3 个以上自动启用占位符模式。

```text
项目名称：{项目名称}
建设周期：{开始日期} 至 {结束日期}
```

集合型数据（一行一条）用「集合名 + 序号 + 属性」：

```text
{活动1名称}  {活动1交付物}  {活动1结束时间}
```

- 同名占位符全局同值
- 属性词走同义词桥接：模板写「交付物」，excel 写 `Work Product / 工作产物 / 工作成果` 都能对上
- **表格行数会按数据条数自动增减**：数据 5 条、模板 4 行 → 自动扩到 5 行；数据 4 条、模板 6 行 → 缩到 4 行

无占位符的老模板会自动回落到「结构推断」模式（靠表头 + 空白单元格推断），精度明显更低，仅作兼容兜底。

## API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/` | 前端页面 |
| GET | `/api/health` | 健康检查 |
| GET | `/api/llm/status` | 模型接入状态 |
| POST | `/api/llm/test` | 测试 Key 连通性 |
| POST | `/api/analyze` | 上传模板 + 参考资料，返回字段三态 |
| POST | `/api/answers` | 提交缺口补充回答，重新判定 |
| POST | `/api/export` | 导出填充后的 docx |

导出的文档末尾会自动附两个附录：**依据索引**（每项标到第几段 / 哪个单元格）和**待补充事项**。取不到值的字段正文写成 `【待补充：xxx】`，不留白——留白最危险，看起来像写完了。

## 目录结构

```
backend/
  app/
    core/models.py       数据契约（字段、状态、报告）
    parsers/
      placeholder.py     占位符解析（含 Word 把 {xx} 拆成多个 run 的修复）
      docx_template.py   无占位符模板的结构推断
      analyzer.py        两种模式的统一入口
      doc_parser.py      docx/pdf/xlsx/pptx → 带定位的语料块
    services/
      dataset.py         结构化表格对齐（集合+序号+属性 → 单元格）
      expander.py        按数据条数规划扩行/缩行
      retriever.py       取值链 ①②④
      aligner.py         取值链 ③ + 三道校验
      llm.py             DeepSeek 客户端与结果缓存
      exporter.py        docx 写回与附录生成
  scripts/
    make_samples.py      生成示例模板与参考文件
    smoke.py             端到端冒烟
    test_llm.py          校验层测试（40 项，不需要 Key）
```

## 测试

```bash
cd backend
python scripts/test_llm.py   # 校验层 + 链路接线，40 项，无需 Key
python scripts/smoke.py      # 端到端冒烟，输出判定报告
```

`test_llm.py` 里专门覆盖了「引文是真的、取值是编的」这种最隐蔽的伪造，以及缓存二次运行零调用等场景。

## 已知限制

- **任务索引在进程内存里**。单进程运行没问题，但 `uvicorn --workers N` 下导出会 404，上线前需换成 Redis / SQLite。
- 带纵向合并或跨列合并的表格行不参与增减，宁可少填也不破坏版式。
- 扩行上限 50 行，防止一份长 excel 把文档撑爆。
- 语义对齐能减少追问，但不会消灭追问。例如资料里只有 Target Date、模板要「开始时间」，系统仍会问你——「预计完成」不等于「开始」。
